# Лила в.2 — зафиксированные решения

Источник: переписка из предыдущего чата (Claude). Здесь — только решения, без рассуждений.
Канон правил: книга Хариша Джохари «Лила. Игра самопознания» (рус. изд. «София», 1999).
Старый проект v1 (/var/www/lila/app) НЕ развивать и НЕ переносить из него контент (truth/, cells.json, transitions.json и т.п.). Новый проект — с нуля.

## 1. Продукт
- PWA: мобильный (приоритет портретная ориентация) + ПК. Языки: русский и английский сразу. Санскрит (деванагари/транслит) — декоративный слой.
- Flow: стартовый экран → правила (повторно не показывать, если игрок не первый раз) → вопрос/намерение + согласие → игровое поле + кубик → бросок кнопкой → движение фишки → окно со значением клетки + чат с ИИ-ведущим.
- ИИ-ведущий ведёт игру; ответ на вопрос строится по всей цепочке клеток/змей/стрел партии.
- Сохранение и продолжение партии после выхода; выгрузка чата/итога (PDF, ru/en).
- Экрана «история ходов» для пользователя нет. Журнал событий нужен внутренне: восстановление партии, итог, дневник.
- Монетизация в перспективе: сейчас всё бесплатно, но сразу закладываем users id, entitlements, лимит обращений к ИИ на партию. Платёжки позже (ЮKassa / CloudPayments).
- Атмосфера: аутентичная, допустимые техники НЛП для погружения. Настройки: язык, атмосферные эффекты (полные/лёгкие/выкл), крупные цифры, быстрый режим.

## 2. Правила (канон, без пользовательских переключателей)
- Доска 9×8 = 72 клетки, змейкой снизу вверх (1–9 слева направо, 10–18 справа налево…).
- Все фишки стартуют на 68 «Космическое Сознание». Вход только по 6: фишка на 1 («Рождение»), оттуда 6 шагов → клетка 6.
- Любая 6 даёт повторный бросок, на любой стадии (в т.ч. когда её нельзя использовать для хода).
- Серии шестёрок разрешаются ОДНИМ ходом в конце серии (режим «series»; «perRoll» не используем):
  - ровно 3 шестёрки подряд + другое число: серия сгорает, возврат на клетку до серии (при входе — на 1), ход только на 4-й бросок;
  - 4+ шестёрок: сумма всех очков серии, один ход от клетки до серии (при входе — отсчёт, дающий вход через клетку 1).
- Змеи/стрелы срабатывают автоматически на итоговой клетке хода.
- Перелёт > 72: ход не исполняется. С 69 годятся 1–3, с 70 — 1–2, с 71 — только 1. С 67–68 на 68 шагнуть нельзя: ждём змею 72→51, оттуда 3 → 54 → стрела → 68.
- Победа: точно на 68 (ходом или стрелой 54→68). 66 привела точно на 68 — финиш сразу, без доп. броска.
- Опечатка перевода («с 71 единица ведёт на 68»): делаем по геометрии доски 71+1=72 → змея → 51.
- Стрелы: 10→23, 17→69, 20→32, 22→60, 27→41, 28→50, 37→66, 45→67, 46→62, 54→68.
- Змеи: 12→8, 16→4, 24→7, 29→6, 44→9, 52→35, 55→3, 61→13, 63→2, 72→51.
- Названия клеток — по главе 2 книги (клетка 6 — «Заблуждение (моха)», 29 — «Отсутствие религиозности (адхарма)», 31 — «План святости (якша-лока)», 47 — «План нейтральности»). Исправлять артефакты OCR («ъ» вместо «ь»).
- Тексты толкований Джохари защищены АП (© 1980, 1993 H. Johari; перевод © «София», 1999). В приложении — собственные тексты по смыслу. Рисунки доски из книги тоже не копировать.

## 3. Архитектура (слои)
- PRESENTATION (арты+UI, ничего не решает) → CHOREOGRAPHER (очередь: событие → сцена) → APP/FLOW (иерархическая машина состояний) → GAME CORE (чистые функции, детерминированный ГСЧ с seed) → CONTENT DATA (всё данными: клетки, переходы, i18n) → PERSISTENCE (event sourcing).
- Два времени: логика мгновенна, хореограф играет красиво; анимацию можно пропустить/ускорить без поломки логики.
- RuleSet — данные (johari-ru-v1), но без выбора пользователем.
- Стек: Node LTS изолированно (nvm, отдельный пользователь lila; системный Node v20 не трогать — от него зависит vitamins), TypeScript strict, Vite, React. Тяжёлый 3D (three.js) — под вопросом: решено делать на СТАТИЧНЫХ артах + CSS/canvas-анимации (кубик, фишка, свиток, дым, мерцание). 
- Сервер: nginx отдаёт статику + /api/* → Node 22 + Fastify (127.0.0.1:3100), systemd-сервис, отдельный пользователь lila. БД: предлагался PostgreSQL 16 (MySQL уже занят vitamins — решение подтвердить). Гостевой режим: партия в IndexedDB, перенос в аккаунт при входе. Auth: одноразовый код на email, httpOnly cookie (Secure/HttpOnly/SameSite), rate-limit.
- API (черновик): POST /api/auth/code, POST /api/auth/verify, GET /api/games/current, POST /api/games, POST /api/games/:id/roll (бросок считает сервер — античит + будущая монетизация), GET /api/games/:id/result, GET /api/games/:id/pdf.
- Проверки: юнит-тесты правил, property-based (фишка в 1..72, финал только на 68), Монте-Карло 1 млн партий, детерминизм по seed, визуальная регрессия Playwright.

## 4. Визуал
- Стиль: древние манускрипты, дворцы-прасады, миниатюры Пала, гуджаратская доска с инкрустацией (садели). Палитра: охра, сепия, индиго, слоновая кость, золото.
- На доске — только цифры (+ значки змеи/стрелы в углу клеток-переходов). Миниатюры 72 клеток — НЕ фон клеток, а иллюстрации в окне-потхи и крупном плане. У каждого ряда свой мягкий тон. Цифра — в латунном медальоне, контраст ≥4.5:1. Фон клетки — однотонная фактура дерева, орнамент только на рамке. Название — по тапу/ховеру (LOD при приближении).
- Окна адаптивные через 9-slice (border-image), рисуются ОДНОЙ картинкой, не по частям. Кнопки — 3-slice, состояния (hover/active/disabled) кодом. Свиток: стержень (торец 1 картинка + mirror), древко бесшовной полосой, бумага бесшовно по вертикали. Дым и мерцание светильников — кодом на canvas (частицы + процедурная/спрайтовая текстура), видео с альфа — нет.
- Попадание на змею/стрелу: фишка встаёт → свиток с артом кобры / лука со змеями → подпись перехода → «Принять» → скольжение по траектории → окно клетки назначения + чат (ведущий толкует обе клетки).
- prefers-reduced-motion: минимум анимаций; пауза rAF в фоне; меньше частиц на смартфоне.

## 5. Темп анимаций (pace.ts, M1) — по симуляции 50k партий
diceRoll 700, diceSettle 150, stepPerCell 160 (потолок stepMaxTotal 1100 на путь), landPause 200, snake 1300, arrow 1100, overshoot 450, tripleSixReset 900. speedFactor: fast ×2, reduced-motion ×4. Цель: ~1 мин чистой анимации на медианную партию, ≤3 мин на p90.

## 7. Формат работы с сервером
- AI не подключается к VPS. Код: песочница → zip → wget по ссылке (или WinSCP). Обратная связь — вывод терминала в чат.
- Команды блоком «ВСТАВИТЬ В ТЕРМИНАЛ», границы «КОПИРОВАТЬ ОТСЮДА/ДОСЮДА».
- vitamins — запрещено трогать. Пароли/.env в чат не присылать. Позже: ufw, SSH-ключ, отдельный пользователь lila.
